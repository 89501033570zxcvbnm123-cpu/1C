# Журнал подтверждённых знаний агента по 1С

Этот файл хранит повторно полезные технические выводы. Перед работой ищите записи по области, симптому и названию механизма 1С.

## Формат записи

```text
### YYYY-MM-DD — Краткое название

- Область: подсистема, язык или инструмент.
- Контекст/симптом: при каких условиях проявилось.
- Подтверждённый вывод: что установлено.
- Проверка: как вывод был подтверждён.
- Практическое правило: что агент должен делать в дальнейшем.
```

## Записи

### 2026-08-08 — Безопасная проверка необязательных свойств структуры

- Область: встроенный язык 1С, работа со структурой и методом `Свойство()`.
- Контекст/симптом: синтаксическая проверка кода с выходным параметром `Свойство()` и ошибка выполнения `Поле объекта не обнаружено`, когда результат `ПрочитатьJSON()` не содержал необязательное поле внешнего API.
- Подтверждённый вывод: прямое обращение к отсутствующему свойству структуры завершает выполнение исключением. Перед чтением необязательного свойства его наличие нужно проверять методом `Свойство()`; переменная, используемая как выходной второй параметр этого метода, должна быть предварительно определена.
- Проверка: требование к выходному параметру подтверждено синтаксической проверкой 1С; отсутствие свойства воспроизведено фактической трассировкой выполнения и сопоставлено с исходным кодом прямого обращения к полю, которое официальная документация внешнего API определяет как необязательное.
- Практическое правило: данные JSON внешних систем считать неполными по умолчанию. Перед чтением необязательного поля вызывать `Структура.Свойство(ИмяСвойства, Значение)` с заранее определённой переменной `Значение`, отдельно проверять заполненность и формат значения и не запускать обновление конфигурации до успешной повторной синтаксической проверки.

### 2026-08-08 — Смещение `Сред()` после двухсимвольного префикса

- Область: встроенный язык 1С, разбор строковых кодов.
- Контекст/симптом: из строки с идентификатором применения `01` извлекался 14-символьный GTIN выражением `Сред(Строка, ПозицияПрефикса + 3, 14)`; первая цифра GTIN терялась, а в результат попадал следующий за GTIN символ.
- Подтверждённый вывод: позиции символов в строковых функциях 1С отсчитываются с единицы. Если `Найти()` вернул позицию начала двухсимвольного префикса, данные сразу после него начинаются с `ПозицияПрефикса + 2`.
- Проверка: смещение подтверждено подсчётом позиций на формате `01` + 14 символов GTIN и сопоставлением с исходным кодом, в котором рядом был сохранён исправленный вариант `+ 2`.
- Практическое правило: при извлечении подстроки после найденного префикса прибавлять длину префикса, а не длину плюс один; проверять граничные позиции на минимальном тестовом примере.

### 2026-08-10 — Скобки внутри серийного номера GS1 нельзя удалять глобально

- Область: интеграция 1С с Честным знаком, нормализация кодов GS1 перед отправкой в API.
- Контекст/симптом: API возвращал сведения без `expirationDate` только для марок, у которых серийная часть после AI `21` содержала символ `(` или `)`; исходный код удалял все скобки во всей строке двумя вызовами `СтрЗаменить()`.
- Подтверждённый вывод: скобки могут быть допустимыми символами серийного номера. Глобальное удаление `(` и `)` изменяет уникальный код марки. Удалять можно только скобки, которыми во входном представлении выделены структурные AI `(01)` и `(21)`.
- Проверка: во всех десяти проблемных марках из двух тестовых документов скобка находилась внутри серийной части; успешные позиции не демонстрировали этот признак. Официальная документация Честного знака допускает скобки в наборе специальных символов серийных кодов и требует передавать AI `01` и `21` без выделяющих их скобок.
- Практическое правило: разбирать представление `(01)<GTIN>(21)<серийный номер>` позиционно: удалить только оболочки `(01)` и `(21)`, а серийную часть переносить без замен. Перед массовым тестом проверять, что подготовленный код посимвольно совпадает с зарегистрированным КМ.

### 2026-08-12 — HTTPS-клиент на HTTP-порту Apache

- Область: веб-публикация 1С через Apache, диагностика подключения мобильного клиента.
- Контекст/симптом: клиент не подключался к публикации на порту 80; в `access_log` Apache фиксировались запросы с телом, начинающимся байтами TLS ClientHello (`\\x16\\x03\\x01`), и ответом HTTP 400.
- Подтверждённый вывод: клиент отправлял HTTPS/TLS на порт, где Apache настроен только на обычный HTTP. Доступ клиента до сервера и порта при этом уже подтверждён самим появлением его IP-адреса в журнале Apache.
- Проверка: `httpd.exe -t` вернул `Syntax OK`, Apache слушал `0.0.0.0:80` и `[::]:80`; HTTP-запрос к публикации вернул 200, защищённые маршруты веб-сервисов — ожидаемый 401, а запросы клиента с TLS-заголовком — 400.
- Практическое правило: при `\\x16\\x03\\x01` и HTTP 400 в `access_log` сначала сверять пару «протокол — порт»: для публикации без SSL выбирать HTTP и порт 80; HTTPS использовать только при реально настроенном SSL-виртуальном хосте и слушателе, обычно на 443.

### 2026-08-12 — Права пользователя публикации для мобильного клиента

- Область: веб-публикация 1С, авторизация мобильного клиента и права пользователя информационной базы.
- Контекст/симптом: Apache и маршруты публикации были доступны, но мобильный клиент не мог завершить подключение под отдельным пользователем 1С.
- Подтверждённый вывод: доступность Apache и успешная аутентификация сами по себе не гарантируют работу интеграции; пользователю публикации нужны все права и роли, которые проверяют вызываемые сервисы конфигурации. В данном случае подключение заработало после выдачи недостающих прав.
- Проверка: после изменения только набора прав пользователя, без изменения Apache и параметров сети, подключение мобильного клиента стало успешным.
- Практическое правило: если HTTP-маршрут публикации доступен, отдельно проверять права пользователя 1С на вызываемые сервисы и данные. Для постоянной эксплуатации выдавать минимально достаточную роль интеграции; полные права допустимы как диагностическая проверка, но не как предпочтительная итоговая настройка.
