# Журнал подтверждённых знаний агента по 1С

Этот файл хранит повторно полезные технические выводы. Перед работой ищите записи по области, симптому и названию механизма 1С.

## Формат записи

```text
### YYYY-MM-DD — Краткое название

- Область: подсистема, язык или инструмент.
- Контекст/симптом: при каких условиях проявилось.
- Подтверждённый вывод: что установлено.
- Проверка: как вывод был подтверждён.
- Практическое правило: что агент должен делать в дальнейшем.
```

## Записи

### 2026-08-08 — Безопасная проверка необязательных свойств структуры

- Область: встроенный язык 1С, работа со структурой и методом `Свойство()`.
- Контекст/симптом: синтаксическая проверка кода с выходным параметром `Свойство()` и ошибка выполнения `Поле объекта не обнаружено`, когда результат `ПрочитатьJSON()` не содержал необязательное поле внешнего API.
- Подтверждённый вывод: прямое обращение к отсутствующему свойству структуры завершает выполнение исключением. Перед чтением необязательного свойства его наличие нужно проверять методом `Свойство()`; переменная, используемая как выходной второй параметр этого метода, должна быть предварительно определена.
- Проверка: требование к выходному параметру подтверждено синтаксической проверкой 1С; отсутствие свойства воспроизведено фактической трассировкой выполнения и сопоставлено с исходным кодом прямого обращения к полю, которое официальная документация внешнего API определяет как необязательное.
- Практическое правило: данные JSON внешних систем считать неполными по умолчанию. Перед чтением необязательного поля вызывать `Структура.Свойство(ИмяСвойства, Значение)` с заранее определённой переменной `Значение`, отдельно проверять заполненность и формат значения и не запускать обновление конфигурации до успешной повторной синтаксической проверки.

### 2026-08-08 — Смещение `Сред()` после двухсимвольного префикса

- Область: встроенный язык 1С, разбор строковых кодов.
- Контекст/симптом: из строки с идентификатором применения `01` извлекался 14-символьный GTIN выражением `Сред(Строка, ПозицияПрефикса + 3, 14)`; первая цифра GTIN терялась, а в результат попадал следующий за GTIN символ.
- Подтверждённый вывод: позиции символов в строковых функциях 1С отсчитываются с единицы. Если `Найти()` вернул позицию начала двухсимвольного префикса, данные сразу после него начинаются с `ПозицияПрефикса + 2`.
- Проверка: смещение подтверждено подсчётом позиций на формате `01` + 14 символов GTIN и сопоставлением с исходным кодом, в котором рядом был сохранён исправленный вариант `+ 2`.
- Практическое правило: при извлечении подстроки после найденного префикса прибавлять длину префикса, а не длину плюс один; проверять граничные позиции на минимальном тестовом примере.

### 2026-08-10 — Скобки внутри серийного номера GS1 нельзя удалять глобально

- Область: интеграция 1С с Честным знаком, нормализация кодов GS1 перед отправкой в API.
- Контекст/симптом: API возвращал сведения без `expirationDate` только для марок, у которых серийная часть после AI `21` содержала символ `(` или `)`; исходный код удалял все скобки во всей строке двумя вызовами `СтрЗаменить()`.
- Подтверждённый вывод: скобки могут быть допустимыми символами серийного номера. Глобальное удаление `(` и `)` изменяет уникальный код марки. Удалять можно только скобки, которыми во входном представлении выделены структурные AI `(01)` и `(21)`.
- Проверка: во всех десяти проблемных марках из двух тестовых документов скобка находилась внутри серийной части; успешные позиции не демонстрировали этот признак. Официальная документация Честного знака допускает скобки в наборе специальных символов серийных кодов и требует передавать AI `01` и `21` без выделяющих их скобок.
- Практическое правило: разбирать представление `(01)<GTIN>(21)<серийный номер>` позиционно: удалить только оболочки `(01)` и `(21)`, а серийную часть переносить без замен. Перед массовым тестом проверять, что подготовленный код посимвольно совпадает с зарегистрированным КМ.

### 2026-08-12 — HTTPS-клиент на HTTP-порту Apache

- Область: веб-публикация 1С через Apache, диагностика подключения мобильного клиента.
- Контекст/симптом: клиент не подключался к публикации на порту 80; в `access_log` Apache фиксировались запросы с телом, начинающимся байтами TLS ClientHello (`\\x16\\x03\\x01`), и ответом HTTP 400.
- Подтверждённый вывод: клиент отправлял HTTPS/TLS на порт, где Apache настроен только на обычный HTTP. Доступ клиента до сервера и порта при этом уже подтверждён самим появлением его IP-адреса в журнале Apache.
- Проверка: `httpd.exe -t` вернул `Syntax OK`, Apache слушал `0.0.0.0:80` и `[::]:80`; HTTP-запрос к публикации вернул 200, защищённые маршруты веб-сервисов — ожидаемый 401, а запросы клиента с TLS-заголовком — 400.
- Практическое правило: при `\\x16\\x03\\x01` и HTTP 400 в `access_log` сначала сверять пару «протокол — порт»: для публикации без SSL выбирать HTTP и порт 80; HTTPS использовать только при реально настроенном SSL-виртуальном хосте и слушателе, обычно на 443.

### 2026-08-12 — Права пользователя публикации для мобильного клиента

- Область: веб-публикация 1С, авторизация мобильного клиента и права пользователя информационной базы.
- Контекст/симптом: Apache и маршруты публикации были доступны, но мобильный клиент не мог завершить подключение под отдельным пользователем 1С.
- Подтверждённый вывод: доступность Apache и успешная аутентификация сами по себе не гарантируют работу интеграции; пользователю публикации нужны все права и роли, которые проверяют вызываемые сервисы конфигурации. В данном случае подключение заработало после выдачи недостающих прав.
- Проверка: после изменения только набора прав пользователя, без изменения Apache и параметров сети, подключение мобильного клиента стало успешным.
- Практическое правило: если HTTP-маршрут публикации доступен, отдельно проверять права пользователя 1С на вызываемые сервисы и данные. Для постоянной эксплуатации выдавать минимально достаточную роль интеграции; полные права допустимы как диагностическая проверка, но не как предпочтительная итоговая настройка.

### 2026-08-13 — Авария `mngui.dll` при нажатии на заголовок пользовательской группы формы списка

- Область: управляемый интерфейс 1С 8.5, пользовательская настройка формы, УНФ 3.0.
- Контекст/симптом: в УНФ 3.0.13.330 форма `Документ.ЗаказПокупателя.Форма.ФормаСписка` была изменена штатной командой изменения формы: под динамическим списком размещена пользовательская группа «Детали» с таблицей номенклатуры. Нажатие на заголовок этой группы стабильно вызывает аварийное завершение тонкого клиента; Windows фиксирует `1CV8C.exe`, `mngui.dll` и исключение `0xc0000005`. Сбой наблюдался на платформах 8.5.1.1343 и 8.5.1.1423 с близкими смещениями внутри `mngui.dll`.
- Подтверждённый вывод: переустановка платформы и смена её сборки не устраняют дефект; авария детерминированно запускается обработкой конкретной сохранённой пользовательской компоновки управляемой формы. Внутренний код `mngui.dll` запрашивает у объекта интерфейс, получает `0x80004002` (`E_NOINTERFACE`), оставляет выходной указатель нулевым и затем разыменовывает его без проверки результата. Имя `mngui.dll` в событии указывает на место падения интерфейсного механизма, но не на повреждение файла DLL и не на случайную порчу памяти.
- Проверка: на копии клиент-серверной базы открыт список заказов с проблемной компоновкой; одиночное нажатие на заголовок «Детали» немедленно воспроизвело системный диалог 1С «К сожалению, возникла непредвиденная ситуация». Разбор шести штатных минидампов платформ 8.5.1.1236, 8.5.1.1343 и 8.5.1.1423 показал во всех случаях `0xc0000005`, чтение адреса `0x0`, `RCX=0`, `RAX=0x80004002` и одну и ту же последовательность машинных инструкций по соответствующим смещениям `mngui.dll`. Файлы платформы 8.5.1.1423 имеют действительные цифровые подписи 1С; в списке загруженных модулей аварийного процесса сторонних внедрённых DLL не обнаружено.
- Практическое правило: при повторяемом падении `mngui.dll` сначала проверять сохранённые пользовательские настройки формы и точный элемент, вызывающий аварию. Безопасный первичный обход — вернуть стандартный вид проблемной формы или удалить только её пользовательскую настройку; исправление платформы подтверждать повторным тестом того же сценария и дампом, а не заменой отдельной DLL.

### 2026-08-13 — Apache не запускается после смены версии платформы 1С

- Область: веб-публикация 1С через Apache на Windows.
- Контекст/симптом: служба Apache установлена с автоматическим запуском, но остановлена; `httpd.exe -t` завершается ошибкой `Cannot load .../wsap24.dll`, а HTTP-порт не прослушивается.
- Подтверждённый вывод: директива `LoadModule _1cws_module` содержала абсолютный путь к каталогу удалённой версии платформы, тогда как `wsap24.dll` присутствовал только в каталоге установленной новой версии. Из-за отсутствующего DLL вся конфигурация Apache не загружается.
- Проверка: сопоставить путь из `LoadModule` с фактически установленными каталогами платформы и наличием `bin/wsap24.dll`; затем обязательно выполнить `httpd.exe -t` и убедиться в `Syntax OK` до запуска или перезапуска службы.
- Практическое правило: после установки, обновления или удаления версии платформы 1С проверять путь к модулю веб-расширения Apache и тестировать конфигурацию; для Apache Win64 использовать DLL той же архитектуры и предназначенную для Apache 2.4.

### 2026-08-14 — Старые остатки бакалеи не требуют обязательной маркировки

- Область: интеграция 1С с «Честным знаком», учёт частично маркированных остатков бакалейной продукции.
- Контекст/симптом: одновременно имеются старые немаркированные остатки и новые маркированные поступления; предлагалось заказать коды и промаркировать все старые остатки.
- Подтверждённый вывод: по пункту 4 постановления Правительства РФ от 30.11.2024 № 1682 бакалейная продукция, произведённая или ввезённая в РФ до даты начала обязательного нанесения средств идентификации для соответствующей товарной группы, может реализовываться без маркировки до окончания срока годности. Обязательная маркировка таких остатков кодами не требуется.
- Проверка: правило сопоставлено с текстом постановления № 1682 и разъяснением официального сообщества «Честного знака» «До какого числа можно было промаркировать остатки бакалейной продукции?», которое прямо ссылается на пункт 4 постановления.
- Практическое правило: перед настройкой смешанного учёта в 1С разделять товары по коду товарной группы и дате производства или ввоза. Старые допустимые остатки продавать без кода до истечения срока годности; маркированные поступления учитывать и продавать с кодом. Не рекомендовать заказ кодов на старые остатки без отдельного нормативного основания или специального сценария перемаркировки.

### 2026-08-14 — Немаркированные остатки пищевых растительных масел продаются до окончания срока годности

- Область: интеграция 1С и ККТ с «Честным знаком», пищевые растительные масла и масложировая продукция.
- Контекст/симптом: после начала обязательного сканирования кодов на кассе требуется продать масло без Data Matrix и определить, допустим ли такой сценарий.
- Подтверждённый вывод: по пункту 6 постановления Правительства РФ от 27.05.2024 № 676 немаркированные растительные масла, произведённые или ввезённые в РФ до даты обязательной маркировки соответствующего вида упаковки, разрешено реализовывать без средства идентификации до окончания срока годности. Для стеклянной и полимерной потребительской упаковки контрольная дата — 1 октября 2024 года, для иных видов потребительской упаковки — 1 февраля 2025 года.
- Проверка: правило и даты сопоставлены с постановлением № 676 и официальными разъяснениями сообщества «Честного знака» «Требуется ли маркировка растительных масел, произведенных до обязательной маркировки?» и «Что делать, если контрагент направил растительные масла без кодов маркировки?».
- Практическое правило: в 1С раздельно учитывать законные старые немаркированные остатки и новые маркированные поступления. Старые остатки проводить на ККТ как обычный немаркированный товар до окончания срока годности; маркированные товары продавать со сканированием Data Matrix. Масло, произведённое или ввезённое после применимой контрольной даты и поступившее без кода, не принимать в обычный оборот — обращаться к поставщику для возврата или согласованной маркировки.

### 2026-08-14 — Сохранение ручных цен в режиме DataMobile «Изменять» зависит от совпадения строки

- Область: интеграция DataMobile с 1С:Управление торговлей 11, загрузка результатов подбора в документ «Реализация товаров и услуг».
- Контекст/симптом: после подбора реализации на ТСД и внесения результата в 1С у строк товаров пропадали произвольно заданные цены; требовалось обновлять только фактическое количество и заполнять подбор кодов маркировки.
- Подтверждённый вывод: режим `Изменять` сохраняет реквизиты только тогда, когда результат ТСД найден в уже существующей строке. В модулях DataMobile 26.05.2026 v.2 и 24.08.2026 v.1 поиск выполняется как минимум по номенклатуре, характеристике и, если она есть в табличной части, упаковке. При отличии упаковки создаётся новая строка. В версии 24.08.2026 v.1 режим `Изменять` по-прежнему не сохраняет снимок исходной табличной части перед обнулением, а штатный перенос цены в новую строку по-прежнему реализован только для ветки, где серия хранится непосредственно в строке товара; у обычной немаркированной позиции цена остаётся нулевой. Для автоматического завершения формы проверки и подбора кодов маркировки в реализации предназначен параметр `Завершение подбора КМ в исходном документе`.
- Проверка: на копии УТ11 после обмена документа `Т1-УПД07618` идентификаторы всех строк изменились, количество и номенклатура сохранились, а цена и суммы стали нулевыми; после ручного заполнения цен следующий обмен находил уже созданные DataMobile строки и сохранял цены. В документе `Т1-УПД07647` при фактически установленном в шаблоне режиме `Дополнять` исходные строки с ценами остались, а рядом появились новые строки без цен; после переключения шаблона на `Изменять` значение было сохранено и подтверждено повторным открытием карточки. Причина подтверждена исходным кодом `ДатаМобайл_АРМДиспетчера`: режим 3 сначала обнуляет количество, затем ищет строку с учётом упаковки, а перенос цены при создании строки ограничен условием наличия серии в основной табличной части. При ограничении доработки шаблоном дополнительно подтверждено, что `Код` этого справочника имеет числовой тип: сравнение `Шаблон.Код = "000000002"` не выполняло блок, корректное условие — `Шаблон.Код = 2`.
- Практическое правило: при загрузке в существующий документ с ручными ценами выбирать `Изменять`, но отдельно проверять совпадение упаковки исходной и возвращённой строки. Если старые документы используют другое представление упаковки, одной настройки режима недостаточно: нужно выровнять настройки базовых единиц/упаковок либо переносить цену из снимка исходной табличной части. Восстановление только в ветке создания новой строки недостаточно: при частичном выполнении задания часть позиций может быть найдена в существующих строках. Тесты также подтвердили, что восстановление перед общей `ОбработатьСтрокуТЧ` может быть отменено последующей дополнительной обработкой или обработчиком произвольного вида цены; окончательное место восстановления следует выбирать после этих этапов и перед записью документа, а результат обязательно подтверждать новым обменом. При поиске снимка по номенклатуре и характеристике цену допустимо переносить только при ровно одном совпадении; несколько совпадений неоднозначны и требуют устойчивого идентификатора строки. Для маркировки включать блок маркировки и при необходимости `Завершение подбора КМ в исходном документе`.

### 2026-08-14 — Правила сопровождения собственных изменений в расширениях 1С

- Область: доработка сторонних и внутренних расширений 1С в проектах PORT.
- Контекст/симптом: собственные вставки должны быть заметны при сравнении и не теряться среди кода поставщика; по свойствам расширения должно быть видно количество последовательных изменений PORT.

### 2026-08-14 — Перенос служебных и временных каталогов сервера 1С на Windows

- Область: администрирование клиент-серверной 1С под Windows.
- Контекст/симптом: системный диск заполнялся служебными данными кластера и временными файлами процессов `ragent`, `rmngr`, `rphost`.
- Подтверждённый вывод: каталог кластера переносится сменой параметра `-d` в `ImagePath` службы после полного переноса прежнего `srvinfo`; временные файлы процессов переносятся установкой пользовательских `TEMP` и `TMP` для учетной записи службы. Изменения начинают действовать после полного завершения серверных процессов и перезапуска службы. Учетной записи службы необходим полный доступ к обоим новым каталогам.
- Проверка: на Windows-сервере с платформой 8.5 служба под `USR1CV8` успешно запущена с `-d "D:\1C_Server\srvinfo"`; `ragent` и `rmngr` используют новый путь, новые файлы `v8_*.tmp` создаются в `D:\1C_Server\Temp`, а HTTP-вызов информационной базы возвращает 200. Старый `srvinfo` отсутствует, старый Temp пуст.
- Практическое правило: перед переносом зафиксировать исходный `ImagePath`, остановить службу и убедиться в завершении всех серверных процессов; не запускать сервер с пустым новым `srvinfo`, иначе будет создан новый кластер. После запуска проверять командные строки процессов, наличие прежнего идентификатора кластера, доступность информационной базы и фактическое создание временных файлов в новом каталоге.
